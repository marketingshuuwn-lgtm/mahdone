# عقد جودة واجهة مَهَد

هذا العقد يحدد ما يفحصه مدقق الواجهة تلقائيًا. لا يغير المنتج ولا يفرض تصميمًا جديدًا؛ وظيفته كشف الانحرافات قبل أي إصلاح.

| المجال | القاعدة الآلية | سبب الفحص |
|---|---|---|
| الإجراء الأساسي | كل صفحة تشغيلية لها إجراء أساسي واحد يحمل تسمية واضحة، وتُقارن بصمته البصرية ببصمة الإجراء المعتمدة. | منع اختلاف «مهمة جديدة» و«مشروع جديد» و«طلب الإذن» بلا معنى سلوكي. |
| الأيقونات | كل رمز Phosphor داخل عنصر تحكم يجب أن ينتج glyph مرئيًا، وكل زر أيقونة يحتاج اسمًا قابلًا للوصول. | منع أزرار طرق العرض أو رموز الإجراءات الفارغة. |
| المرشحات وطرق العرض | المجموعة يجب أن يكون لها اسم واضح، ووضع نشط قابل للقراءة، ولا تُخلط وظيفة المرشح مع التنقل أو الإنشاء. | منع عناصر مثل «تصفية المهام» من الظهور كعنوان بلا دور واضح. |
| الوصولية البنيوية | لا أدوار ARIA غير مكتملة، ولا عناصر تحكم متداخلة، ولا حقول اختيار بلا اسم. | لا ينبغي أن يكون الجلد الجديد أقل قابلية للاستخدام بلوحة المفاتيح أو قارئ الشاشة. |
| القراءة | النصوص التشغيلية الصغيرة تُفحص ضد تباين WCAG AA. | ظهور النص مهم بقدر ظهور البطاقة أو اللون. |
| الاتساق | تُجمع بصمات الإجراءات الأساسية حسب الحجم والاستدارة واللون والخط؛ أي اختلاف يحتاج سببًا صريحًا. | يميّز التنوع المقصود عن تعدد أنماط عشوائي. |
| سلامة التشغيل | أخطاء الصفحة ووحدة التحكم تفحص في كل مسار رئيسي. | لا تسليم لمعاينة تخفي خطأ تشغيل خلف بناء ناجح. |

## نطاق النسخة الأولى

يفحص المدقق: مساحة العمل، المشاريع، التقدم، المفكرة، والإعدادات. ويُشغَّل على رابط المعاينة الحقيقي، لا على HTML ساكن، حتى يرصد حالة البيانات والتفاعلات الفعلية.
